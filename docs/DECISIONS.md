# Decision log

- **DEC-001** Build path: Claude Code cloud sessions + GitHub; Colab pulls the code at a pinned tag.
- **DEC-002** Master keeps original audio levels; loudness is measured in Phase 0 and applied only at render — normalising early would flatten the crowd-noise spikes Phase 4 depends on.
- **DEC-003** Phase 0 uses only Python stdlib (unittest, dataclasses), PyYAML and FFmpeg, so tests run anywhere, including offline.
- **DEC-004** No footage, audio or large binaries in the repo, ever.
- **DEC-005** Config path defaults. `drive_root: /content/drive/MyDrive/AIEditor` (where Colab mounts Drive); `inbox: inbox` and `work: work` are relative to `drive_root`; `local_work: /content/aieditor_work` (Colab local disk). `drive_root` and `local_work` must be absolute.
- **DEC-006** Which config keys each stage's fingerprint covers. Only keys that change what a stage writes: S2 `video.target_fps`, `audio.track_index`; S3 `video.master_codec`, `video.master_crf`, `video.master_preset`, `audio.master_sample_rate`; S4 all `analysis.*`; S5 all `qc.*`; S0, S1, S6 none. `paths.*` are in no fingerprint, so moving or renaming the Drive folder does not force a re-run. S3 sees target_fps and the audio track through media_info.json (its input), so changing them re-runs S2 onwards via the resume rule. `loudness.target_lufs` is used by no Phase 0 stage (render only). Fingerprint = SHA-256 of the sorted key/value JSON; `1` and `1.0` hash the same. run_report's `config_fingerprint` covers every non-path key.
- **DEC-007** Contract details not fixed by PHASE0.md. Stage ids `s0_preflight` … `s6_stage_out`. One status vocabulary everywhere: pass / warn / fail (a marker is only pass or warn, since markers are written only after success). `video.rotation` is clockwise degrees (0/90/180/270); width/height are coded (pre-rotation) pixels. `AudioTrack.index` and `audio.track_index` count audio streams only (0 = first audio stream). Timestamps are ISO 8601 with timezone. Marker output paths are relative to the match work dir, `/`-separated, no `..`. Fingerprints are 64-char lowercase hex. `totals.minutes_per_footage_minute` is null when footage is 0. Unknown fields are rejected. schemas/*.json are generated from core/contracts.py, never hand-edited.
- **DEC-008** Fixture details. All fixtures are 20 s except F10 (10 min, 30 fps). F2 sections: 60 fps 0–7 s, 45 fps 7–13 s, 30 fps 13–20 s, so flashes land inside sections, not on the joins. Audio is AAC 44.1 kHz stereo, so S3's resample to 48 kHz is exercised. F5 track 1 is mono 48 kHz with 440 Hz beeps at +2.5 s, so a test can tell which track a master used. F3 uses the classic `rotate=90` meaning (display matrix −90°). F9 is the first half of an F1-style MP4, so the index (moov) is missing.
- **DEC-009** Target FFmpeg is 6.1.1 (Ubuntu build `6.1.1-3ubuntu5`) on both Colab and the Claude Code cloud box; owner checked Colab on 2026-09-26. Code and tests use FFmpeg 6 options (`-fps_mode`, `-display_rotation`) with no fallbacks for older builds. S0 (increment 0.2) will record the version on every run, so a Colab image change will show up in run_report.json.
- **DEC-010** S0 Preflight is exempt from the resume rule: it runs on every run, is never skipped and writes no stage marker (owner, 2026-09-26). Its checks (Drive mounted, free disk, FFmpeg, GPU) describe the current Colab machine, which changes after every disconnect; A5 already expects a re-run to skip S1–S2, not S0. Contract change: a stage marker's `stage` can no longer be `s0_preflight`.
- **DEC-011** S6 Stage-out is split (owner, 2026-09-26). Copying a stage's outputs to the Drive work dir is part of that stage (S1–S5) and is skipped with it; outputs are copied first and the marker last, so a disconnect mid-copy never leaves a marker without its outputs. Writing `run_report.json` + `summary.txt` runs on every run, is never skipped and writes no marker, because the report describes the current run. Contract change: a stage marker's `stage` can no longer be `s6_stage_out`.
- **DEC-012** S1 Stage-in runs on every run, writes no marker and never forces later stages to re-run (owner, 2026-09-26). Its output is the raw file on Colab's local disk, which a disconnect always wipes, so under the resume rule it could never be skipped and would re-run the whole pipeline. On resume it recomputes match_id and copies back from Drive only the files the first unfinished stage needs; it copies nothing to Drive, so DEC-011's per-stage copy applies to S2–S5. The resume rule's output check looks in the Drive work dir. A5 reworded to "re-run skips S2 and restarts S3". Contract change: a stage marker's `stage` can no longer be `s1_stage_in`.
- **DEC-013** Notebook flow for 0.2 (owner, 2026-09-26). C1 only mounts Drive; C2 downloads the code; C3 installs PyYAML; running the C4 form cell runs S0 → S1 → S2. C4's recording field takes a number from the inbox listing (newest first) or a file name; leave it empty to see the listing. C5 (live progress %) arrives in 0.3.
- **DEC-014** Match-ID time is the file's modified time in UTC (owner, 2026-09-26). Hash layout: SHA-256 over the size as decimal text, then the first 8 MiB, then the last 8 MiB (the two overlap for files under 16 MiB); first 6 hex chars.
- **DEC-015** Tags (owner, 2026-09-26). After the owner merges an increment's PR, Claude pushes a tag `v0.N.0` at the merge commit on main and reports it; C2's `tag` field defaults to the latest tag. This permission covers tags only.
- **DEC-016** S2 detection rules. Frame durations are the gaps between sorted video packet timestamps (zero gaps dropped). Variable frame rate = more than 1% of frame durations differ from the median by more than 10%. `target_fps: auto` picks 60 when the median frame rate is at least 45 fps, else 30; a warning appears when the master fps differs from the recording's by more than 1 fps. An `audio.track_index` beyond the last track fails S2 (no silent fallback). A warning appears when the chosen audio track starts more than one master frame away from the video; `start_offset_s` is reported as ffprobe measures it, which AAC priming can make ~24 ms early (see F7). Rotation is rounded to the nearest 90°; `display_aspect` uses the coded size times the sample aspect ratio, swapped for 90°/270°. Cover-art streams are ignored. Nothing is written if any check fails; media_info.json goes to the local work dir and to Drive `work/<match_id>/`.
- **DEC-017** S0/S1 details. S0: Drive counts as mounted when `drive_root` and `inbox` are folders; the recording must be a plain file name in the inbox; free space is measured on the disk that holds `local_work`; GPU name comes from `nvidia-smi` (none if absent); GPU encoder availability = a 0.1 s `h264_nvenc` test encode succeeds (recorded only, never fails S0); every problem is reported together. S1: the local copy is `local_work/<match_id>/source<ext>` (extension lower-cased), written as `.partial` and renamed only after the size check; a same-size local copy is reused unless *force re-run* is ticked (in 0.2 that is all force re-run does).
- **DEC-018** `GITHUB_TOKEN` is optional in C2 because the repo is public: C2 uses the secret when it exists and clones anonymously otherwise, so the notebook keeps working if the repo is made private later.

- **DEC-020** CLAUDE.md rule 14 changed from "never merge" to "merge only when the owner explicitly says so" (owner, 2026-09-26). The owner asked Claude to merge PR #1; the rule now matches that.
- **DEC-021** Match-ID time comes from the recording time in the file name (owner, 2026-09-26), replacing DEC-014's modified time. Reason: clip 1 (`Record_2026-08-21-21-54-38_….mp4`, recorded 21 Aug) got `20260926-1410-61cab8` because the modified time Colab sees on Drive is the upload time. The first valid `YYYY-MM-DD-HH-MM-SS` in the file name is used as written (phone local time, no timezone conversion); names without one fall back to the modified time in UTC. The hash part is unchanged. S1 prints which source it used. Clip 1's ID becomes `20260821-2154-61cab8`; its old Drive folder `work/20260926-1410-61cab8/` is no longer used and can be deleted.
- **DEC-022 (proposed)** S3 master details. Constant frame rate comes from each frame's timestamp (FFmpeg `fps` filter, `start_time=0`), never from re-timing by frame count; frames are repeated to fill gaps (clip 1's 348 ms stall stays visible) and dropped where two land in one slot. Rotation is applied by FFmpeg's autorotate and the display matrix is gone from the master. Audio: the configured track, `aresample` to 48 kHz with `async=1:first_pts=0` (a late start is padded with silence from 0 s, gaps filled, overlaps trimmed, nothing stretched), AAC 192 kb/s, channel count kept, no level change. Video: libx264 with the config's CRF/preset, yuv420p, `+faststart` so the master can start playing from Drive before it fully downloads. S3 re-probes the master and fails unless every frame lasts exactly 1/target_fps and no rotation metadata remains. Observed on fixtures: master audio ends 4–15 ms after the video; AAC stores audio in 21.3 ms blocks, longer than one 60 fps frame (16.7 ms), so S5's "audio vs video ≤ 1 frame" check may need a tolerance decision in 0.5.
- **DEC-023 (proposed)** S4 analysis details. One decode of the local master writes `analysis.mp4` (width from config, height scaled to keep the aspect and rounded to even, fps from config, libx264 CRF 23 veryfast, no audio) and `analysis.wav` (PCM 16-bit, rate and channels from config). Each must end within one analysis frame of the master or S4 fails and keeps nothing. A master without sound gives no WAV and a warning. At 10 fps a one-frame event (a 33 ms flash) can fall between samples, and each analysis frame shows the picture up to half an analysis frame after its timestamp.
- **DEC-024** Notebook from 0.3, following the PHASE0 notebook spec and DEC-013: C4 only chooses (inbox listing, or a check that the typed number/name is in the inbox); C5 runs S0 → S4 and prints progress: S1/S4 every 10–25%, S3 every 5% with position, speed (x real time) and time left, then S3's total time against D1's 1.5x limit. Stage logs are kept on Colab's local disk only until 0.4 adds the run report.
